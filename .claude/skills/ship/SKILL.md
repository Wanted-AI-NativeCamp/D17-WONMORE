# /ship — 기능 하나 출시하기

입력: `$ARGUMENTS` (비어 있거나 `F5` 같은 기능 번호)

기준 문서
- 기능 목록·상태: `feature/WONMORE/PRD.md` §4 표 (✅ 완료 · 🟡 일부 완료 · ⬜ 아직 안 만듦)
- 작업 규칙: 저장소 루트 `CLAUDE.md` — 이 스킬의 모든 단계에서 지킨다
- 앱 위치: `feature/WONMORE/app/`

## 1단계. 기능 고르기

**번호가 없을 때 (`/ship`)**
1. PRD §4 표를 읽고 상태가 ⬜ 또는 🟡 인 기능을 찾는다.
2. 아래 순서로 하나를 추천한다.
   - 다른 기능이 먼저 필요하다고 적힌 것(예: "F2·F3 블록 분리가 먼저 필요")은 뒤로 미룬다.
   - 남은 것 중 번호가 가장 작은 것.
3. 사용자에게 이렇게 말하고 **멈춘다. 코드를 고치지 않는다.**
   ```
   다음 추천: F? · 기능 이름 (상태)
   - 할 일: 완료 기준을 쉬운 말로 1~2줄
   - 남은 기능: F?, F?, F?
   만들려면 /ship F? 라고 불러 주세요.
   ```

**번호가 있을 때 (`/ship F5`)**
- PRD §4 표에서 그 번호를 찾는다. 없으면 "PRD에 F?가 없어요"라고 알리고 멈춘다.
- 이미 ✅ 이면 "이미 완료된 기능이에요. 다시 손볼까요?"라고 묻고 멈춘다.

## 2단계. 만들기 전에 알리기 (3줄)
- 무엇을 만들지 (PRD 완료 기준 그대로)
- 고칠 파일 목록
- 새 패키지가 필요하면 **여기서 허락을 받고 멈춘다** (CLAUDE.md 규칙)

## 3단계. 만들기
- 계산·저장 로직은 `lib/`에, 화면은 `app.py`에. `lib/`에서 `st.*`를 쓰지 않는다.
- 사용자 데이터 파일은 `lib/storage.py`로만 읽고 쓴다. `.userdata/` 파일을 직접 지우거나 고치지 않는다.
- `Data/` 원본은 읽기만 한다. 원본에 없는 설명을 지어내지 않는다.
- 사용자에게 보이는 문구와 에러는 한국어로 쓴다. 주석도 한국어로 쓴다.
- 기록이 하나도 없어도 화면이 열리게 만든다.
- 수업 데이터 구조를 바꿨다면 `python scripts/build_lessons.py`를 다시 실행한다.

## 4단계. 검사하기
1. `tests/`에 이 기능의 테스트를 추가한다. 화면 동작은 `streamlit.testing.v1.AppTest`로, 저장 위치는 `tmp_path`로 바꿔서 테스트한다.
2. `feature/WONMORE/app`에서 `.venv/Scripts/python -m pytest -q`를 실행한다.
3. 실패하면 고치고 다시 실행한다. 3번 고쳐도 실패하면 멈추고 실패 내용을 한국어로 알린다.
4. 검수 에이전트(`.claude/agents/`)가 있으면 이 기능을 검수하게 한다. 지적 사항은 고치거나 사용자에게 알린다.

## 5단계. PRD 갱신
- PRD §4 표에서 이 기능의 상태를 ✅(또는 🟡 + "남은 것")로 바꾼다.
- 완료 기준과 다르게 만든 부분이 있으면 그 칸에 적는다.

## 6단계. 보고 (3줄 요약)
```
✅ F? · 기능 이름 출시
- 바뀐 파일: ...
- 테스트: N개 통과
- 확인해 볼 곳: http://localhost:8501/?day=D3 ...
```
- **커밋·push는 하지 않는다.** "커밋할까요?"라고 묻고, 사용자가 허락하면 그때 한다.
- 이번에 실수가 있었다면 CLAUDE.md "실수에서 배운 규칙"에 한 줄 추가할지 묻는다.

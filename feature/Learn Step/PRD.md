# LearnFlow PRD v0.2

- 상위 브랜드: WONMORE
- 서비스: LearnFlow
- 버전: v0.2 (v0.1 대비 변경 이력은 맨 아래 참고)
- 날짜: 2026-11-05
- 목표: 개인 개발 MVP (원티드 AI Native Camp 교육생 대상)
- 핵심 결정: **원본 HTML 수업 자료를 자동 분석해 구간(section) 단위로 재구성하고, 구간별 탭으로 따라가며 진행 상황과 어려움을 기록한다.**

## 1. 제품 정의
LearnFlow는 매일 제공되는 HTML 수업 자료를 자동 분석해 **구간별 탭으로 나눠 보기 좋게 다시 보여주고**, 학습자가 구간을 따라가며 **잘 따라가고 있는지, 어디서 막혔는지** 기록하고 Day별로 다시 확인하는 웹 서비스다.

### 문제 가설
- 수업 자료 하나가 길어서(6~11개 구간, 최대 약 350KB) 지금 어디쯤인지 알기 어렵다.
- 지난 수업 자료를 찾고, 보던 위치로 돌아가기 번거롭다.
- 학습 중 막힌 지점과 해결 방법을 구간과 연결해서 남기기 어렵다.

### MVP 성공 기준
사용자가 Day를 선택하고, 고정 탭으로 구간을 이동하며 학습하고, 구간마다 진행 상태와 어려움을 기록하고, 다시 접속했을 때 보던 위치에서 이어볼 수 있다.

## 2. 대상 사용자
- 우선: AI Native Camp 초심자, 학습 내용을 기록하려는 학습자
- 숙련자: 빠르게 훑어보고 필요한 구간만 찾는 학습자
- 학습 모드(초심자/숙련자)를 선택할 수 있고, 모드에 따라 포인트 컬러가 바뀐다 (§9).

## 3. 핵심 정책
1. **원본 파일은 수정하지 않는다.** `Data/` 원본 HTML은 읽기 전용으로 두고, 빌드 스크립트가 분석해 만든 결과물만 화면에 쓴다.
2. **보여주는 방식은 바꾸되 내용은 지어내지 않는다.** 구간 나누기, 레이아웃 정리, LearnFlow 디자인 적용은 허용한다. 원본에 없는 설명을 생성하거나 요약하지 않는다.
3. **구간 = 원본의 `<section id>` 단위.** 구간 제목은 원본 `<h2>`를 그대로 쓴다.
4. **기록은 Day와 구간에 연결한다.** 하나의 구간에 여러 기록을 남길 수 있다.
5. **원본 메뉴(`<nav class="toc">`)와 원본 스크립트는 쓰지 않는다.** LearnFlow의 sticky 탭이 원본 메뉴를 대신한다.
6. **개인 데이터는 localStorage의 `learnflow.v1.*` 키에만 저장한다.** 원본이 쓰던 키(`wb1014:*` 등)는 읽거나 쓰지 않는다. 계정·기기 간 동기화는 제공하지 않는다.
7. **수업 자료와 분석 결과물은 GitHub에 올리지 않는다.** `Data/`와 빌드로 생성된 수업 JSON은 `.gitignore`에 넣는다. 재배포 권한을 확인하기 전에는 공개 배포하지 않고 로컬에서만 실행한다.

## 4. 기능

### P0
| ID | 기능 | 완료 기준 |
|---|---|---|
| F01 | Day 목록 | D1~D10, D17 총 11개 Day를 카드로 표시. 카드에 구간 수와 진행률 표시 |
| F02 | HTML 자동 분석 | 빌드 스크립트가 `Data/*.html`을 읽어 Day·제목·구간(id, h2 제목, 본문)을 JSON으로 생성 |
| F03 | 구간 재구성 화면 | 원본 본문을 LearnFlow 디자인으로 다시 그림. 코드 블록·표·팁·단계 목록 같은 원본 구성요소를 공통 컴포넌트로 바꿔 보여줌 |
| F04 | Sticky 구간 탭 | 스크롤해도 상단에 고정된 탭으로 구간 이동. 현재 구간 강조, 탭이 많으면 가로 스크롤 |
| F05 | 원본 인터랙션 재구현 | 코드 복사 버튼, 단계 체크박스, 직군·OS별 내용 전환 탭이 LearnFlow 안에서 동작 |
| F06 | 구간별 진행 표시 | 구간마다 `시작 전 / 진행 중 / 완료` 상태. 탭과 Day 카드에 진행률 표시 |
| F07 | 따라가기 체크인 | 구간 끝에서 "잘 따라가고 있나요?" 질문에 `잘 따라감 / 조금 헤맴 / 막힘` 중 선택. 헤맴·막힘을 고르면 어려웠던 점 입력칸이 열림 |
| F08 | 학습 기록 | 구간에서 `어려움 / 해결 / 발견` 유형으로 기록 작성. 공백만 있는 기록은 저장하지 않고 안내 |
| F09 | Day 기록 패널 | 상세 화면 옆 패널에서 그 Day의 체크인과 기록 전체를 구간별로 묶어 보여줌. 기록 삭제는 확인 후 해당 기록만 삭제 |
| F10 | 이어보기 | 마지막으로 보던 Day·구간을 기억해 홈에 "이어보기" 버튼 표시. 누르면 해당 구간으로 이동 |
| F11 | 학습 모드 | 초심자(블루) / 숙련자(퍼플) 선택. 선택은 저장되고 포인트 컬러에 반영 |
| F12 | 반응형 | 창 너비를 줄여도 잘림·가로 스크롤 없이 사용 가능 (§9 기준) |

- 공개 배포 (재배포 권한 확인 전)

## 5. IA
- **홈**: 서비스 소개, 학습 모드 선택, 이어보기 버튼, Day 카드 목록
- **Day 상세** (노트 페이지를 따로 두지 않음)
  - 상단: Day 제목 + sticky 구간 탭 + 진행률
  - 본문: 선택한 구간의 재구성된 콘텐츠 → 구간 끝 체크인 → 기록 작성
  - 옆 패널: 이 Day의 체크인·기록 전체 (구간별 묶음). 좁은 화면에서는 하단 시트로 전환

## 6. 사용자 흐름
**학습 진행**: 홈 → Day 선택(또는 이어보기) → 탭으로 구간 이동 → 내용 따라 하기·체크박스 체크 → 구간 끝 체크인 → (막혔다면) 어려운 점 기록 → 다음 구간

**기록 확인**: Day 상세 → 옆 패널에서 구간별 기록 확인 → 기록을 누르면 해당 구간으로 이동 → 필요하면 삭제 확인 후 삭제

## 7. 데이터 구조
```ts
// 빌드 스크립트 생성물 (git 제외)
type Lesson = {
  id: string;        // 'D1', 'D2', ... 'D17'  ← Day 기준 (§8)
  day: number;       // 1, 2, ... 17
  title: string;     // 원본 <title>에서 'Dn 워크북 ·' 접두사 제거
  sourceFile: string;// 'D01_1014.html'
  sections: Section[];
};

type Section = {
  id: string;        // 원본 <section id> 값, 예: 'install'
  title: string;     // 원본 <h2> 텍스트
  order: number;
  html: string;      // 정제된 본문 (script·nav 제거, 허용 태그만)
  checkKeys: string[]; // 원본 단계 체크박스 data-k 목록
};

// localStorage (사용자 데이터)
type SectionProgress = {
  status: 'todo' | 'doing' | 'done';
  checked: string[];  // 체크한 단계의 data-k
  updatedAt: string;  // ISO 8601
};

type CheckIn = {
  id: string;
  lessonId: string;
  sectionId: string;
  level: 'good' | 'struggling' | 'stuck';
  note?: string;      // struggling·stuck일 때 어려웠던 점
  createdAt: string;
};

type LearningNote = {
  id: string;
  lessonId: string;
  sectionId: string;
  type: 'difficulty' | 'solution' | 'discovery';
  content: string;
  createdAt: string;
};
```

### localStorage 키 (모두 `learnflow.v1.` 접두사)
| 키 | 값 |
|---|---|
| `learnflow.v1.progress` | `{ [lessonId]: { [sectionId]: SectionProgress } }` |
| `learnflow.v1.checkins` | `CheckIn[]` |
| `learnflow.v1.notes` | `LearningNote[]` |
| `learnflow.v1.resume` | `{ lessonId, sectionId, updatedAt }` |
| `learnflow.v1.prefs` | `{ mode: 'beginner' \| 'advanced' }` |

- 원본 스크립트를 실행하지 않으므로 원본 키와 충돌하지 않는다. LearnFlow 코드도 `learnflow.v1.` 밖의 키를 건드리지 않는다.
- 저장 실패(용량 초과, 비공개 모드 등) 시 실패를 안내하고 성공으로 표시하지 않는다.
- 구조가 바뀌면 `v2` 키로 옮기고 이전 데이터를 변환한다.

## 8. 콘텐츠와 Day 기준
- **Day 표기는 D1, D2, D3… 를 기준으로 한다.** 날짜(10/14 등)는 화면에 표시하지 않는다.
- 파일명 → Day 매핑: `D01_1014.html` → `D1`, …, `D17_1105.html` → `D17`. 앞자리 0을 뺀다.
- 보유 자료: D1~D10, D17 (11개). D11~D16은 자료가 없으므로 목록에 표시하지 않는다.

| Day | 제목(원본 기준) | 구간 수 |
|---|---|---|
| D1 | 클로드 업무자동화 워크북 | 7 + 스크립트 생성 구간 |
| D2 | HTML이 화면이 되는 원리 + 조별 AI 서비스 리스트 | 6 |
| D3 | Claude Code | 8 |
| D4 | 틀린 걸 찾아 스킬로 가르치기 | 11 |
| D5 | Git으로 같이 일하기 | 9 |
| D6 | 무료 API로 나만의 서비스 만들기 | 6 |
| D7 | 파이썬으로 API 키 지키기 + 하루 3번 오는 서비스 | 6 |

구간 수는 1차 분석 값이며 빌드 스크립트 결과로 확정한다.

### 자동 분석 규칙
- D2~D17: `<section id="..." class="sec">`를 구간으로, 그 안의 첫 `<h2>`를 구간 제목으로 쓴다.
- D1: `class="sec"`가 없고 일부 구간을 스크립트(`MODULES` 배열)가 만든다. 빌드할 때만 격리된 환경(jsdom)에서 스크립트를 실행해 최종 DOM을 얻는다. 실패하면 D1은 수동 매핑으로 대체한다.
- 원본 구성요소 → LearnFlow 컴포넌트 매핑 (출현 빈도 순)

| 원본 class | 용도 | LearnFlow 컴포넌트 |
|---|---|---|
| `codebar` + `copy` | 코드 블록 + 복사 버튼 (약 330개) | CodeBlock |
| `chk` / `step` / `steps` | 단계 체크리스트 (약 235개) | StepChecklist (진행률과 연동) |
| `tip` / `hint` | 팁·힌트 | Callout |
| `tbl` / `tblw` | 표 | Table (좁은 화면에서는 가로 스크롤) |
| `tabs` + `data-job` | 직군별 내용 전환 | SegmentedTabs |
| `os-win` / `os-mac` | OS별 안내 | OsSwitch (선택값 저장) |
| `panel` / `card` / `box` | 묶음 영역 | Card |

- 매핑에 없는 구성요소는 기본 스타일로 보여주고 깨지지 않게 한다. 빌드 로그에 미처리 class 목록을 출력한다.
- 외부 링크(github.com, nodejs.org 등)는 새 탭으로 연다. 외부 스크립트(cdn.jsdelivr.net)는 불러오지 않는다.

## 9. 디자인
- **공통 디자인 시스템**: WONMORE 공통 디자인 시스템(`WONMORE/Designsystem.md`)을 따른다. WONMORE 공통 디자인 시스템은 **원티드 몽타주(Montage) 디자인 시스템을 참고**해 만든 것으로 가정한다.
- **컬러 토큰**: `feature/Learn Step/colorsystem.md` 값을 쓴다.
  - **초심자 모드 = 블루** (`--beginner: #4E8BFF`)
  - **숙련자 모드 = 퍼플** (`--advanced: #A76AF2`)
  - 홈 = 블루+퍼플 조합, 경고 = 오렌지 (`--warning`)
  - 포인트 컬러는 주요 행동(CTA), 선택된 탭, 진행 표시에만 쓴다.
- **진행 상태 표시**: 색만으로 구분하지 않는다. `시작 전 ○ / 진행 중 ◐ / 완료 ✓`처럼 아이콘과 텍스트를 같이 쓴다.
- **체크인 상태**: 잘 따라감 / 조금 헤맴 / 막힘도 아이콘과 텍스트를 같이 쓴다. 막힘에는 경고색(오렌지)을 쓴다.
- **카드·간격·모서리**: 흰 카드, 얇은 테두리, 카드 20px / 버튼 12px / 태그 999px 모서리, 8px 간격 단위.
- **애니메이션**: 150~300ms ease-out, `prefers-reduced-motion` 존중.
- **반응형**: 창을 줄여서 보는 경우를 기본으로 고려한다.

| 너비 | 레이아웃 |
|---|---|
| 1280px 이상 | 본문(최대 760px) + 옆 기록 패널(360px) |
| 768~1279px | 본문 전체 너비, 기록 패널은 토글로 열리는 오른쪽 드로어 |
| 767px 이하 | 본문 전체 너비, 기록 패널은 하단 시트, sticky 탭은 가로 스크롤 |

- 최소 지원 너비 375px. 어떤 너비에서도 페이지 가로 스크롤 없음 (코드 블록·표 내부 스크롤만 허용).
- 키보드로 탭 이동(←/→), 모든 버튼에 보이는 포커스 표시.

## 10. 테스트 / 인수 기준
- [ ] 11개 Day가 D1~D10, D17 순서로 표시된다
- [ ] 빌드 스크립트가 11개 파일을 모두 분석하고, 구간 수가 원본 `<section>` 수와 일치한다
- [ ] 원본 메뉴가 보이지 않고, sticky 탭이 스크롤 중에도 상단에 고정된다
- [ ] 탭을 누르면 해당 구간으로 이동하고, 현재 구간이 강조된다
- [ ] 코드 복사, 단계 체크박스, 직군·OS 전환이 동작한다
- [ ] 구간 진행 상태가 탭과 Day 카드에 반영된다
- [ ] 체크인에서 헤맴·막힘을 고르면 입력칸이 열리고 저장된다
- [ ] 공백만 있는 기록은 저장되지 않고 안내가 나온다
- [ ] 옆 패널에 그 Day의 기록이 구간별로 모여 보이고, 다른 Day 기록과 섞이지 않는다
- [ ] 삭제 확인 후 해당 기록만 삭제된다
- [ ] 새로고침 후 진행 상태·기록·모드가 유지된다
- [ ] 다시 접속하면 이어보기로 마지막 구간에 도착한다
- [ ] localStorage에 `learnflow.v1.` 밖의 키가 생기지 않는다

## 11. 일정 (약 4시간, 노트 페이지를 상세 화면 옆 패널로 합침)
| 시간 | 작업 |
|---|---|
| 0~20분 | Vite 초기화, `.gitignore`, 토큰 CSS |
| 20~80분 | 빌드 스크립트: 구간 분석·정제·JSON 생성, D1 처리 |
| 80~130분 | Day 목록 + 상세 + sticky 탭 + 구간 렌더링 (CodeBlock, Callout, Table 우선) |
| 130~165분 | 진행 표시 + StepChecklist + 이어보기 |
| 165~205분 | 체크인 + 기록 작성 + 옆 패널 (조회·삭제) |
| 205~240분 | 반응형 점검, 학습 모드 컬러, 수동 QA |

- 가장 큰 위험은 빌드 스크립트(원본 구성요소 매핑)다. 80분 시점에 끝나지 않으면 매핑되지 않은 구성요소는 기본 스타일로 두고 다음 단계로 넘어간다.
- SegmentedTabs·OsSwitch가 시간 안에 안 되면 모든 내용을 펼쳐서 보여주고 P1로 미룬다.

## 12. 후속 서비스 연동 방향
WONMORE 아래 LearnFlow(학습 탐색)·PeerLoop(동료 학습)·GrowthLog(성장 기록)·AI Tutor(복습)를 별도 서비스로 소개한다. 이번 MVP에서는 다른 서비스와의 API 연동이나 데이터 공유를 구현하지 않는다. 체크인의 `stuck` 기록은 나중에 PeerLoop·AI Tutor로 넘길 후보 데이터다.

## 13. 남은 확인 사항
- 원본 수업 자료의 재배포 허용 여부 (허용 전까지 공개 배포 금지)
- 원티드 몽타주 실제 토큰 값과 `colorsystem.md` 값 일치 여부
- 학습 모드에 따라 컬러 외에 무엇을 다르게 할지 (예: 초심자는 힌트 기본 펼침)
